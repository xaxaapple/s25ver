# The Galaxy S25 (SM-S931B) port

OneiOS began on the Galaxy S24 Ultra (SM-S928, SM8650). This is the second target: the **base Galaxy S25, SM-S931B,
codename `pa1q`, SM8750 ("sun", Snapdragon 8 Elite for Galaxy)**, One UI 8.5 firmware `S931BXXSBCZG3`. The design does
not change (XNU runs as a process, xnuhost, on One UI's kernel); what changes is the host it meets. Marks: [F] read
from a source named beside it, [I] inferred, [U] unknown until the probe has run on the phone.

## What the S25 is, as far as it is known

| | S24 Ultra (SM8650) | S25 (SM8750) | Source |
|---|---|---|---|
| CPU | 2 x A520, 5 x A720, 1 x X4 (Arm, ARMv9.2, SVE2) | 2 prime + 6 performance **Oryon** cores (Qualcomm, implementer 0x51), no little cores, **no SVE/SVE2/SME** | [F] the OneOS fork's probe of an S25, 2026-10-23 (`app-android/README.md`); topology [F] Qualcomm's product brief |
| Core ids, capacities, frequencies, cache sizes | known (docs/hardware.md) | [U] `tools/probe/s25-probe.sh` writes `cpu.txt` | |
| GPU | Adreno 750, KGSL `chip_id` 0x43051400, `gpu_id` 6770 | Adreno 830; `chip_id` and `gpu_id` [U] (probe: `gpu_kgsl_sysfs.txt`, `gpu_gpuctl.txt`) | |
| Panel | 1440x3120 @120 Hz (QHD+) | **1080x2340** @120 Hz (FHD+, 6.2 in, about 416 ppi) | [F] fork probe: one 1080 x 2340 panel |
| Kernel | GKI 6.1/6.6 | 6.6.127-android15 on the probed S25; yours on One UI 8.5 [U] (probe: `kernel_version.txt`) | [F] fork probe |
| Root | KernelSU | KernelSU Next 3.4.0 on the probed S25 | [F] fork probe |
| Haptics | Cirrus CS40L26A under `sec_vibrator_inputff` | [U] (probe: `haptics_*.txt`); the bridge finds the actuator by the input device's name, so it works if the S25 keeps that name | |
| Bluetooth HAL | HIDL `vendor.bluetooth-1-1-qti` (WCN785x) | [U] (probe: `bt_hal.txt`); Android 16 may have moved the vendor HAL to AIDL, which `runtime/bridges/bt/hci_hidl.c` does not speak | |

Firmware: the probed S25 ran a different build (One UI 9.0, Android 17) than `S931BXXSBCZG3` (One UI 8.5, Android 16).
Everything marked [F] from that probe should be read as "very likely the same on yours"; the probe settles it.

## What was changed for the S25

| Area | Change |
|---|---|
| Display | `xnuhost` fallback panel, the display helper's fallback (`displayctl`, `OneiOSDisplay.java`) and the profile `userland/config/device-iphone18,2.toml` are 1080x2340 @120 Hz. The UI scale stays 3: **360x780 points**, the pixel grid of the iPhone 12 mini / 13 mini; `--scale 2` gives 540x1170. A point is 1/139 inch (the iPhone's 1/153): 44-point targets are 8.0 mm. The artwork set stays the Pro Max's (`artwork-device-subtype` 2868, its assets are certainly in the image); the 12/13 mini's subtype (2340) is an untested alternative [I]. xnuhost's tests and `userland/tests` follow. At 1080x2340 a frame is 10.1 MB (18 MB before). |
| CPU plan (`runtime/bridges/cpu/topology.c`) | Oryon has no little cores. The old rule (lowest capacity = E) would have made the six performance cores an E cluster and left iOS two P cores. Now a Qualcomm core (MIDR implementer 0x51) is never E, and a host whose cores are all P but of different speeds **lends** its slowest cores to the guest as E vCPUs (one in four vCPUs, at least one; 8 vCPUs: 2 E + 6 P), because XNU's AMP scheduler and the iPhone's boot CPU want both kinds. Hosts with all-alike cores and the S24's A520 cores behave as before. Tests with an SM8750-shaped fixture (made-up capacities and frequencies, the real shape): `runtime/bridges/tests/test_bridges.c`, 210 checks. |
| Phone gate in the OneOS fork | The fork only offered iOS on the S24 Ultra, in two places: `OneiosSystem.PROFILE_IDS` (Kotlin) and the preflight of `switcher/assets/oneios_switch.sh`. Both now accept `SM-S931*` / `pa1q` / `SM8750` as well (the fork already has the S25 profile `s-8750`). Its tests and the refusal texts follow. The fork's tests were not run here (Gradle); the workflow `oneos-apk.yml` runs them. |
| Metal translation | `userland/metal/patches/metal2vulkan/` holds the Adreno-generic shader-translation fixes of hakios-arm64e-dada (see below), rebased on the pin; `userland/metal/build.sh` stages them as `9xxx` patches after the base's own. |
| Phone probe | `tools/probe/s25-probe.sh`: read-only; writes `/data/local/tmp/oneios-s25-probe-<time>.tar.gz`. |
| GitHub Actions | `s25-phone-kit.yml` (tests, runtime package and the probe in one artifact), `gpu-patch-check.yml` (do the metal2vulkan patches apply to the pin and type-check). |

## What was taken from hakios-arm64e-dada, and what was not

hakios-arm64e-dada boots XNU **on bare metal** on the Xiaomi 15 (Snapdragon 8 Elite, SM8750, Adreno 830): its own EFI
loader from Mu-Silicium's UEFI, an Android DSU partition for the image, its own kernel drivers (SCMI clocks to 3.52 GHz,
ADSP audio, ath12k Wi-Fi, touch, haptics). OneiOS runs under One UI's Linux kernel, so everything that exists only
because hakios owns the hardware has no place here. Judged from its README, NOTICE and `gpu2/` (the kernel patch itself
was **not** audited line by line, see "Open").

| hakios part | Verdict |
|---|---|
| `gpu2/patches/metal2vulkan-next/0101` large indexed constants to the blob (a table indexed at run time and larger than 4 KiB goes to the constant blob: as a `Private` variable every thread copies it into Adreno scratch, which the hardware backs per fiber; a 192 KiB ramp table per thread was refused) | **Taken**, rebased on the pin (`624bab3`, 24 commits after hakios's base); Adreno-generic, so it matters on an 830 as on any Adreno |
| `0102` blob constant GEP pointers, `0103` block bytes per process | **Taken**, rebased (0102 applies as is, 0103 with offsets) |
| `0104` lone linked function | **Not taken yet**: one hunk fails on the pin (`pipeline/compile.rs`, shipped as `0104-...patch.NEEDS-REBASE`); wants a manual rebase |
| `0201` bridge API adapter, `0202`/`0203` refusing encoder / first-problem log | **Not taken**: they patch UniXNU's `AdrenoMetal` at hakios's base; OneiOS builds Droid-VM's `NativeMetal` at another pin. Candidate for a rebase once the Metal plug-in boots (0202 stops a nil encoder from crashing a process) |
| `mesa-85fda3b-dada.patch` | **Not taken**: Mesa main plus hakios's own kernel-driver ABI (RedwoodGPU). Whether the Mesa pin of OneiOS (`cecc0e9`, Droid-VM) already knows the Adreno 830 [U]; `gpu_gpuctl.txt` and the first Metal run answer it. Turnip builds for Android carry a8xx support in recent Mesa (public Turnip builds of 2026 target it) |
| `nativemetal-dada.patch` (250 KB) | **Not taken**: written against the kernel driver |
| `base/xnuloader`, `uefi-dada/`, DSU, `tools/dada-*.sh`, SCMI/PLL/clock, ADSP/AudioReach, ath12k Wi-Fi, Xiaomi touch panel, CS35L43 amps | Bare-metal or Xiaomi-only: **not applicable** |
| Liquid Glass shader fixes | Reach OneiOS through the metal2vulkan patches above and through the upstream metal2vulkan the pin tracks |

Also checked: OneiOS's metal2vulkan pin is 799 commits after hakios's 720ef1c and 24 after the 0dfdbcd that hakios's
trial upgrade used, so most of hakios's "next" experiments (a trial with 775 more upstream commits: three shader
mismatches against Apple's GPU became zero) are already in the pin.

## What the probe answers

Run `tools/probe/s25-probe.sh` as root (docs/building.md, "Galaxy S25 probe"). Its files, and the decision each feeds:

| File | Decides |
|---|---|
| `cpu.txt` | Oryon MIDR, capacities and frequency tables: replaces the made-up numbers of the SM8750 test fixture; confirms 2 + 6 and the E vCPUs the plan lends |
| `kernel_config.txt`, `kernel_va.txt`, `kernel_modules_udmabuf.txt` | Page size (4 KiB is assumed everywhere), VA bits (patch `0027` assumes the S24's 39 bits), udmabuf limits (the GPU chunking assumes 64 MiB and 1024 runs), pointer authentication, KGSL options |
| `gpu_kgsl_sysfs.txt`, `gpu_nodes.txt`, `gpu_gpuctl.txt` | Adreno 830's `chip_id`/`gpu_id`, whether `drm2kgsl` imports a buffer (the S24 failed with ENOMEM until the VBO fix of `docs/gpu.md` 4.1) and its GPU VA range |
| `display_*.txt`, `input_*.txt` | The 1080x2340 mode ids and the touch screen's axes (the HID bridge scales them to the guest) |
| `haptics_*.txt`, `battery.txt`, `als_*.txt` | Whether the haptics, battery and light-sensor bridges find their nodes |
| `bt_hal.txt`, `bt_lshal.txt`, `audio_hal.txt`, `camera.txt` | HIDL or AIDL Bluetooth on Android 16, audio and camera HALs |
| `selinux_*.txt` | Labels on `/dev/kgsl-3d0` and `/dev/udmabuf`, any denials |

## Open

- Nothing of OneiOS has run on an S25. Every [I] and [U] above is a guess until the probe and a first session.
- The hakios **kernel patch** was not audited for Oryon quirks (system registers, errata, PAC key handling, timer).
  Under Linux most of that is the host's business, but the trapped-instruction paths (`runtime/xnuhost/src/sysreg.c`,
  the `0027` PAC patch) should be read against an Oryon core's behaviour once the probe shows its ID registers.
- hakios's iOS 26 bring-up (`userland/`) was not diffed against OneiOS's iOS 27 userland tweaks.
- Parallel research agents hit the account's usage limit, so no separate research report was written; this file is the
  record.
